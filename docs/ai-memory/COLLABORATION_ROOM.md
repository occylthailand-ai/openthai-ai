## ห้องนี้ทำงานอย่างไร (ตามจริง — ไม่ปั้นแต่ง)

**ข้อเท็จจริงทางเทคนิคที่ต้องเข้าใจตรงกัน:** ระหว่างผู้ช่วย AI ต่างเจ้า (Claude / Copilot /
Gemini / Grok) **ไม่มีช่องทางเทคนิคเชื่อมถึงกันโดยตรง** — ไม่มี shared memory, ไม่มี API
ระหว่างกัน (ยืนยันซ้ำใน `CLAUDE.md` และ `DECISIONS_LOG.md`) ดังนั้น "ห้องสนทนา" ที่ทำได้
จริงคือ **เอกสารกลางที่เจ้าของโปรเจกต์เป็นผู้ส่งต่อ (relay) เข้าไปในแต่ละแพลตฟอร์ม** แล้วนำ
คำตอบกลับมาแปะไว้ที่นี่ — เหมือนที่ `core-philosophy.json` และ `PROJECT_STATUS.md` ถูก
ออกแบบให้ "แปะเข้าไปเปิดหัวการสนทนา" อยู่แล้ว ส่วน GitHub + Vercel เป็นแพลตฟอร์มจริงที่มี
API จึงเชื่อมอัตโนมัติได้ (Claude ใช้งานผ่านเครื่องมือได้โดยตรง)

**ทำไมต้องซื่อตรงเรื่องนี้:** ถ้าทำเป็นว่ามีห้องแชตสดที่ AI ทั้ง 6 คุยกันเองอัตโนมัติ จะเป็นการ
โกหกความสามารถจริง และเปิดช่องให้เนื้อหาที่ AI ตัวหนึ่ง "มโน" ขึ้นมาไหลเข้าไปสร้างของจริง
โดยไม่ตรวจสอบ (เคยเกิดแล้ว — ดู `DECISIONS_LOG.md`: Neo4j, Stripe/USD escrow, ETDA v15.0
ที่ไม่มีอยู่จริงใน repo) ห้องนี้จึงยึด "ground truth เหนือความมั่นใจของถ้อยคำ" เป็นกฎเหล็ก

### รอบการทำงาน (async rounds) — เจ้าของเป็นผู้ relay

1. เจ้าของแปะไฟล์ชุดกลางเข้าไปในแต่ละแพลตฟอร์ม: `PROJECT_STATUS.md` (สถานะจริง, regen ด้วย
   `node scripts/generate-project-status.mjs`), `DECISIONS_LOG.md` (ประวัติ + ข้อที่ถูกปฏิเสธ),
   `docs/ai-memory/core-philosophy.json`, และไฟล์นี้
2. แต่ละฝ่ายเสนอ 1 งานที่ผลกระทบสูงสุด **พร้อมอ้างอิงไฟล์/บรรทัดจริงใน repo** (ไม่ใช่ spec ลอย)
3. เจ้าของนำคำตอบมาแปะในหัวข้อ "บันทึกรอบสนทนา" ด้านล่าง
4. **Claude ตรวจสอบทุกข้อเสนอกับ repo จริงก่อน** (grep/read/run) แล้วลงมือทำเฉพาะข้อที่ผ่าน
   การตรวจสอบ → commit + push สาขาที่ได้รับมอบหมาย → เปิด/อัปเดต PR → บันทึก `DECISIONS_LOG.md`
5. GitHub PR + Vercel preview = หลักฐานจริงว่าอะไรเสร็จ (ไม่ใช่คำกล่าวอ้างว่า "100% passed")

## กฎเหล็กของห้อง (ทุกฝ่ายต้องยึด)

1. **Verify ก่อน build** — grep/อ่านโค้ดจริงก่อนเสมอ; ข้อเสนอที่อ้างถึงไฟล์/ตาราง/endpoint ที่
   ไม่มีจริงใน repo ให้ **หยุดถามเจ้าของ** ไม่ใช่เริ่มสร้างบนฐานที่ไม่มีอยู่ (lesson_01)
2. **ห้ามกล่าวอ้างว่าเสร็จโดยไม่ได้รัน** — "เสร็จ" = รันเซิร์ฟเวอร์/เทส/เรียก endpoint จริงแล้วเห็นผล
3. **ห้าม scrape/เก็บข้อมูล/ติดต่อคนจริงโดยไม่ได้รับความยินยอม** (ยืนยันแล้ว 2026-07-03)
4. **ห้าม push ไปสาขาอื่นนอกจากที่ได้รับมอบหมาย** และ **ห้าม auto-merge เข้า main** โดยไม่มีคนรีวิว
5. **เรื่องกฎหมาย/ความเสี่ยงสูง/ขอบเขตกว้างเกินคำสั่ง → หยุดถามเจ้าของก่อน** (เช่น e-Tax/ETDA + HSM)
6. **สื่อสารกับเจ้าของเป็นภาษาไทย** และบันทึกทุกการตัดสินใจลง `DECISIONS_LOG.md`
