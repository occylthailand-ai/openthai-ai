## 4. ข้อสังเกตและความเสี่ยงที่พบ

### 4.1 มีสอง Schema คู่ขนาน — ความเสี่ยงระดับกลาง ⚠️

**ปัญหา:** พบว่ามีตาราง Affiliate สองชุดในโปรเจกต์:
- **ชุด A** (`aff_users`, `aff_commissions`) — `affiliate-schema.sql` ใช้ rate เริ่มต้น 0.35 (35%)
- **ชุด B** (`affiliates`, `affiliate_conversions`) — `004_affiliate_tracking.sql` ใช้ 0.20–0.40 ตาม tier

หาก deploy ทั้งสองพร้อมกันโดยไม่ระบุ schema ที่ใช้จริง อาจเกิดความไม่สอดคล้องใน commission_rate ที่จ่ายให้ affiliate ได้

**ความเสี่ยงทางกฎหมาย:** ถ้าผู้ใช้ได้รับ commission ต่างจากที่ตกลงในสัญญา → เสี่ยงพิพาทตามประมวลกฎหมายแพ่งและพาณิชย์ มาตรา 653 (สัญญาและข้อตกลง)

**แนะนำ:** ระบุให้ชัดว่า Schema ไหนคือ production — ยุบรวมหรือ deprecated อีกชุด

### 4.2 Admin Key แบบ Static — ความเสี่ยงระดับต่ำ ⚠️

```javascript
// server.js บรรทัด 428
const adminKey = process.env.ADMIN_KEY || 'openthai-admin-2026';
```

Fallback key ถูก hardcode — ถ้า ENV var ไม่ถูก set จะใช้ค่า default ที่คาดเดาได้

**แนะนำ:** ถ้า ENV ไม่มีให้ reject request ทันที แทนที่จะ fallback ไป default

### 4.3 การเพิ่ม Tier 2 ในอนาคต — ต้องระวัง ⚠️

ปัจจุบันระบบ 1 ชั้น = ปลอดภัย แต่ถ้าอนาคตจะเพิ่ม "affiliate ชวน affiliate ได้ค่านำเสนอ" ต้องตรวจว่า:
1. ยังจ่ายจากยอดขายจริงเท่านั้น (ไม่ใช่จากค่าสมัครของคนใหม่)
2. ลึกไม่เกิน 2 ชั้น
3. แจ้งต่อ สคบ. ถ้าเข้าข่าย "ขายตรงหลายชั้น" ตาม พ.ร.บ.ขายตรงฯ มาตรา 3

## 5. เรื่องที่ยังไม่ได้ตรวจ (สิ่งที่ยังไม่ได้ทำ)

| ประเด็น | เหตุผลที่ยังไม่ได้ตรวจ |
|---|---|
| ร่างสัญญา Affiliate (Terms) | ยังไม่มีไฟล์สัญญา — ต้องทำแยกต่างหาก |
| ภาษีเงินได้ affiliate (มาตรา 40(8)) | ต้องอ้างอิงประมวลรัษฎากรและหารือนักบัญชี |
| การหักภาษี ณ ที่จ่าย | ยอดเกิน 1,000 บาทต้องหัก 3% — ยังไม่มี logic ในโค้ด |
| จดทะเบียน สคบ. | ขึ้นกับว่าระบบขยายเป็น multi-tier หรือไม่ |

## 6. สรุปและคำแนะนำลำดับต่อไป

**ระบบปัจจุบัน:** ไม่เข้าข่าย MLM หรือแชร์ลูกโซ่ — ผ่านเกณฑ์ Non-MLM ทั้ง 6 ข้อ

**Action ที่แนะนำก่อน deploy production:**

| ลำดับ | งาน | ผู้รับผิดชอบ | ความเร่งด่วน |
|---|---|---|---|
| 1 | ยุบรวม Schema คู่ขนาน เลือก 1 ชุดเป็น production | `backend-engineer` | สูง |
| 2 | แก้ Admin Key fallback → reject แทน default | `security-guard` | สูง |
| 3 | เพิ่ม logic หักภาษี ณ ที่จ่าย 3% เมื่อยอดเกิน 1,000 บาท | `backend-engineer` + `legal-compliance` | กลาง |
| 4 | ร่างสัญญา Affiliate Terms ระบุ commission_rate ที่จ่ายจริง | `legal-compliance` | กลาง |
| 5 | กำหนดนโยบายลายลักษณ์อักษร: ห้ามเพิ่มชั้นที่ 3 โดยไม่ผ่าน legal review | Mythos | ต่ำ |
