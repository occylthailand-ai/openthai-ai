## 1. ปัญหาที่ Portal นี้แก้

ปัจจุบัน OpenThai.ai มี Portal ครบสำหรับกลุ่ม 1, 2, 3, 5 แต่กลุ่มที่ 4 (ผู้บริโภค) **ยังไม่มีหน้าเฉพาะ** ผู้บริโภคทั่วไปที่ต้องการความช่วยเหลือ 3 ด้านหลัก มักหาช่องทางไม่เจอ:

1. **สิทธิสวัสดิการรัฐ** — ไม่รู้ว่าตนมีสิทธิ์อะไร ตรวจสอบที่ไหน ขอที่ใด
2. **เปรียบเทียบสินค้า** — ข้อมูลกระจัดกระจาย อ่านสเปคเทคนิคไม่เข้าใจ
3. **ย่อยสัญญา/ข้อกำหนด** — ประกัน สัญญาเช่า TOS แอป เงินกู้ — อ่านไม่จบ

## 2. ฟีเจอร์หลัก 4 โมดูล

### 2.1 ตรวจสิทธิ์สวัสดิการ (Welfare Check)

**ปัญหาที่แก้:** ประชาชนไม่รู้ว่าตัวเองได้สิทธิ์อะไรจากรัฐ เพราะแต่ละสิทธิ์อยู่คนละหน่วยงาน

**ฟีเจอร์:**
- ผู้ใช้ตอบคำถาม 5–8 ข้อ (รายได้, อาชีพ, อายุ, สถานะครอบครัว, ที่อยู่)
- ระบบแสดงสิทธิ์ที่น่าจะได้ พร้อมลิงก์หน่วยงานจริง
- **ห้าม:** บอกว่าผู้ใช้ "ได้สิทธิ์แน่นอน" — ต้องบอกว่า "น่าจะมีสิทธิ์ ให้ไปตรวจสอบที่..."

**สิทธิ์ที่ครอบคลุม (ยังไม่ได้วัดว่าครบ):**
| สิทธิ์ | หน่วยงาน | ช่องทางตรวจ |
|---|---|---|
| บัตรสวัสดิการแห่งรัฐ | กรมบัญชีกลาง | welfare.mof.go.th |
| ประกันสังคม (ม.33/39/40) | สปส. | sso.go.th |
| เบี้ยยังชีพผู้สูงอายุ | กรมกิจการผู้สูงอายุ | dop.go.th |
| เบี้ยผู้พิการ | กรมส่งเสริมและพัฒนาคุณภาพชีวิตฯ | dep.go.th |
| สวัสดิการข้าราชการ (กบข.) | กบข. | gpf.or.th |
| กองทุนการออมแห่งชาติ (กอช.) | กอช. | nsf.or.th |

**Guardrail บังคับ:**
- ข้อความทุกคำตอบต้องลงท้ายด้วย "ข้อมูลนี้เป็นแนวทางเบื้องต้น ควรตรวจสอบกับหน่วยงานที่ระบุโดยตรง"
- ไม่แนะนำให้ยื่นเรื่องผ่าน AI — ต้องไปยื่นเองหรือผ่านช่องทางทางการ

---

### 2.2 เปรียบเทียบสินค้าอัจฉริยะ (Smart Product Compare)

**ปัญหาที่แก้:** ผู้บริโภคอ่านสเปคสินค้าไม่เข้าใจ เปรียบเทียบข้ามแบรนด์ไม่ได้

**ฟีเจอร์:**
- วางลิงก์หรือ paste สเปคสินค้า 2–3 รายการ
- ระบบแสดงตารางเปรียบเทียบภาษาไทยเข้าใจง่าย
- ไฮไลท์จุดที่ต่างกันชัดเจน
- แสดง "เหมาะกับใคร" ตามการใช้งานที่ผู้ใช้ระบุ

**ขอบเขตหมวดที่จะรองรับก่อน (Phase 1):**
- สมาร์ทโฟน
- ประกันสุขภาพ
- สินเชื่อบ้าน / สินเชื่อส่วนบุคคล
- เครื่องใช้ไฟฟ้า

**Guardrail:**
- ไม่ "แนะนำ" ว่าควรซื้อตัวไหน — เพียงแสดงข้อมูลเปรียบเทียบ
- ระบุที่มาของข้อมูลทุกครั้ง ห้ามเดาสเปค

---

### 2.3 ย่อยสัญญาและข้อกำหนด (Contract Simplifier)

**ปัญหาที่แก้:** สัญญา TOS / ประกัน / เช่า / สินเชื่อ มักมีภาษากฎหมายที่ประชาชนทั่วไปอ่านไม่เข้าใจ

**ฟีเจอร์:**
- วาง PDF หรือ text สัญญา
- ระบบสรุปเป็น "5 ข้อที่ต้องรู้" ด้วยภาษาธรรมดา
- ไฮไลท์ข้อที่ **เป็นประโยชน์ต่อผู้บริโภค** และข้อที่ **ควรระวัง**
- แสดงคำถามที่ควรถามก่อนเซ็น

**Guardrail บังคับ:**
- ทุกผลลัพธ์มีคำกำกับ: "นี่คือการสรุปเพื่อความเข้าใจเบื้องต้น ไม่ใช่คำวินิจฉัยทางกฎหมาย"
- ไม่บอกว่า "สัญญานี้ยุติธรรม/ไม่ยุติธรรม" — บอกแค่สิ่งที่เขียนไว้
- ถ้าพบข้อสัญญาที่ดูน่าสงสัย ให้ชี้ให้เห็นและแนะนำ "ปรึกษาทนายหรือ สคบ."

---

### 2.4 ช่องทางร้องเรียน (Consumer Rights Guide)

**ปัญหาที่แก้:** ผู้บริโภคที่ถูกละเมิดสิทธิ์ไม่รู้จะร้องเรียนที่ไหน อย่างไร

**ฟีเจอร์:**
- ผู้ใช้เล่าปัญหา (ถูกหลอก, สินค้าไม่ตรงตัวอย่าง, ไม่ยอมคืนเงิน ฯลฯ)
- ระบบแนะนำหน่วยงานที่ถูกต้องพร้อมขั้นตอน
- มี template จดหมายร้องเรียนภาษาไทยให้ edit ได้

**หน่วยงานที่ระบบรู้จัก:**
| ปัญหา | หน่วยงาน | ช่องทาง |
|---|---|---|
| ถูกหลอกซื้อสินค้า | สคบ. | ocpb.go.th / สายด่วน 1166 |
| ถูกธนาคารเรียกดอกเกิน | ธปท. | bot.or.th / 1213 |
| ถูกหลอก Online | กองปราบฯ ไซเบอร์ | thaipoliceonline.com |
| อาหาร/ยา/เครื่องสำอางผิดมาตรฐาน | อย. | fda.moph.go.th / 1556 |
| บริการโทรคมนาคม | กสทช. | npesp.ntc.or.th / 1200 |

## 3. สถาปัตยกรรม UX

```
หน้าแรก Consumer Portal
├── [ตรวจสิทธิ์สวัสดิการ] → Welfare Quiz → ผลลัพธ์ + ลิงก์หน่วยงาน
├── [เปรียบเทียบสินค้า]  → Paste URL/Text → ตาราง
├── [ย่อยสัญญา]         → Upload PDF/Text → สรุป 5 ข้อ
└── [ร้องเรียน]          → เล่าปัญหา → หน่วยงาน + Template
```

**ข้อกำหนด UX บังคับ:**
- Mobile-First (ผู้บริโภคส่วนใหญ่ใช้มือถือ)
- ตัวอักษรขนาดอ่านง่าย ≥ 16px
- รองรับภาษาไทยเต็มรูปแบบ (ไม่มีคำทับศัพท์ที่ไม่จำเป็น)
- ผู้สูงอายุต้องใช้ได้ (WCAG 2.1 AA)

## 4. PDPA และความปลอดภัย

- ไม่บังคับ Login สำหรับโมดูล 2.1 และ 2.3 (ถามคำถามทั่วไปได้เลย)
- ถ้าผู้ใช้วางเอกสารที่มีชื่อ/เลขบัตร: ระบบต้องเตือนให้ลบข้อมูลส่วนบุคคลก่อนส่ง
- ไม่เก็บ content ที่ผู้ใช้วาง — process แล้วทิ้ง (session-only)
- ฐานทางกฎหมาย: ประโยชน์โดยชอบธรรม (Legitimate Interest) + ความยินยอม
